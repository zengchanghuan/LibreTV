# 统一作品资料与中文别名搜索

榜单、片名搜索和推荐使用 `src/lib/work-catalog.ts` 中的统一作品资料。确认后的作品以 `tmdb:movie:ID` / `tmdb:tv:ID` 区分；尚未确认的记录以原始 `title:片名|年份` 保留。仅共享海报出处、相同片名或相同数字 ID 都不会自动合并两部作品。

## 当前数据

2026-11-09 已检查全部 1,405 条榜单记录：1,189 条确认、138 条身份待核实、78 条未找到候选。待核实和未找到的记录继续使用原资料，不生成猜测别名。每条处理结果和拒绝原因见 `work-title-collection-report.json`。

例如《光海，成为王的男人》(2012) 对应 `tmdb:movie:133200`，展示《双面君王》，搜索同时请求这两个中文名称。2019 年电视剧及同名异年电影不会并入该电影；未提供年份或分类的片源先尝试查详情，仍无法确认则单独标记。

## 采集与更新

需要 Node.js、已安装的项目依赖、Python 3.9+。Python 仅使用标准库。

1. 将 TMDB API Read Access Token 配置在本机 `.env.local` 的 `TMDB_API_READ_ACCESS_TOKEN`；文件应保持 0600 权限。环境变量也可使用。API Key 可留作其他 TMDB 工具使用，采集器使用 Bearer Token。
2. `npm run titles:collect` 导出实际 TypeScript 榜单并采集，仅生成本机候选和报告。
3. 检查 `.data/tmdb/title-report.json`。有外部 ID 时通过 TMDB 详情或 IMDb `/find` 关联；否则通过片名＋年份搜索候选，再核对演职员。所有自动确认还必须满足类型、年份和 API 返回的名称对应关系，防止旧资料的错误外链传播。
4. `npm run titles:apply` 发布通过确认的记录。也可 `npm run titles:apply -- --offline` 从缓存重新审核并生成，不访问网络。
5. `npm run titles:test`、`npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 验证后再按项目正常流程提交／部署。

指定条目：

```sh
npm run titles:collect -- --key '光海，成为王的男人|2012'
npm run titles:apply -- --key '光海，成为王的男人|2012' --offline
```

请求约每秒 3 次，最多 3 个工作线程；缓存有效期 30 天，遇到限流／暂时网络错误最多尝试 3 次。可重复运行补齐失败记录。部分采集不会清空未涉及的条目；已重新审核但不再能确认的映射会撤回，网络失败则保留旧映射。

## 数据文件与人工校正

| 文件 | 用途 |
| --- | --- |
| `src/lib/film-poster-data.json` | 既有海报、评分、简介和演职员资料，采集器不改写 |
| `src/lib/work-title-data.json` | 浏览器和服务器共用的轻量作品／别名表 |
| `docs/work-title-evidence.json` | 名称语言、地区、TMDB 端点和关联证据 |
| `docs/work-title-collection-report.json` | 全部条目状态、候选和未通过原因 |
| `config/work-title-overrides.json` | 有证据的人工选择或排除 |
| `.data/tmdb/` | 本机请求缓存和候选，不提交、不进入 Docker 镜像 |

默认展示 TMDB `zh-CN` 返回的中文名，保留港台中文名、英文译名及原名；这不保证该名称在每个片源上最常见。榜单卡片会保留不同的榜单原名。可通过 override 选择另一个有来源的展示名，例如已配置的《黄飞鸿》(1991)。

```json
{
  "某作品|2012": {
    "tmdbId": 12345,
    "mediaType": "movie",
    "evidence": "https://可信资料页/已核实的对应关系",
    "preferredTitle": "TMDB 返回的已核实名称"
  }
}
```

示例 ID 为占位值。指定 ID 必须同时填写类型和人工核实来源，且年份仍须相符；`preferredTitle` 必须存在于 API 返回的名称中。仅调整展示名可只填 `preferredTitle`。`{"skip": true}` 可排除错误候选。人工确认应查看原名、年份、类型和导演／主演，不将模型生成的译名直接发布。

## 在线搜索边界

- 点击榜单携带作品 ID、年份与类型；链接、浏览器返回、服务器和客户端缓存都保留这些条件。
- 每源搜索最多两个经去重的名称：优先展示名和用户／榜单名称。每个名称最多两页，共享 10 秒源预算；同时最多处理六个源。
- 一个名称已返回即可渐进展示；一个源只结算一次健康状态。另一个名称失败不会把已经正常返回的源标记为完全失败。
- 同源同 `vodId` 去重。确认属于同一作品的不同译名合并显示，并保留原始片源名。明确年份／类型冲突及解说、花絮、预告不混入榜单作品。
- 每源最多补查三条缺失资料，仍在同一时间预算内；未确认项独立显示。搜索连接中断也保留已收到的结果。
- 用户手动搜索保留同名作品、不同年份与类型的结果；只有唯一可识别的名称才自动展开别名，不替用户选择有歧义的作品。可从榜单搜索点击“查看全部同名结果”放宽条件。
- 推荐资源查询共用这份别名资料；原有推荐偏好 ID 尽可能保留，曾经冲突的旧 ID 通过保存的片名／年份迁移，避免把不同作品继续合并。

TMDB 只在离线采集时调用，在线搜索不依赖 TMDB 可用性或 Token。Token 不使用 `NEXT_PUBLIC_`，不进入查询 URL、浏览器包、审计资料或 Git。关于页面提供官方 TMDB 标识及要求的致谢文字。
