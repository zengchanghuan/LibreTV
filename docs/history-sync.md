# 账号播放历史同步

登录相同 HomeTV 账号后，网页默认自动同步观看历史和逐集播放进度，不再要求先创建或选择家庭成员。账号以已验证会话中的唯一 ID 隔离；不同用户名／账号之间不会合并记录。

## 使用

两台设备都刷新到新版本并登录同一账号。页面打开、恢复前台、恢复联网及打开历史面板时会同步；观看中的修改约 5 秒后上传，前台每 15 秒拉取一次。右上角「账号同步」或历史面板中的「同步设置」可查看状态、错误和手动重试。

仍选择了家庭成员的设备继续使用该成员独立的历史。需要切回账号默认历史时，在同步设置点击「使用账号历史（自动同步）」。家庭成员与账号历史相互隔离，不自动混合其他成员的记录。共享密码登录和未登录设备保持原有行为，不把匿名记录归给某个账号。

## 旧记录和冲突

第一次启用账号同步时，在原账号 IndexedDB 内先将历史和进度备份到 `syncBackup`，再为可同步记录写入持久待发送队列，最后才请求服务器。不会清空数据库或删除这个备份。首次补传范围为最近 100 条历史和 500 条进度，与服务端保留范围一致；超出范围的原记录仍在备份中。

双方尚未同步过的记录按原始观看时间合并；同一项保留较新的原记录，未来时间戳截断为服务器当前时间。这个首次导入的比较依赖设备原始时间。已同步后的正常修改使用服务器修订号防止旧请求覆盖新版本。旧导入不能复活云端删除标记，历史压缩后的陈旧写入也会被拒绝。本地备份保留冲突前的值，方便恢复。

首次导入标记和备份在同一个 IndexedDB 事务中写入。网络失败会保留队列，下次自动重试；超过单次 400 条限制时分批发送。格式不合法的旧记录留在备份并显示数量，不阻塞其他合法记录。首次导入只执行一次，不会在每次刷新时重复上传旧历史。

## 存储与兼容

- 账号历史继续使用 `hometv-account-<账号 ID>` 本地数据库；不迁移到另一库导致记录暂时不可见。
- 服务端使用已有持久目录中的 `family-<账号 ID>.json`，在 `accountState` 字段保存账号默认历史，原有 `profiles` 和 `states` 字段不变。
- `/api/family/sync` 新增 `scope: "account"` 模式，保存目标只取认证 Cookie 内的账号 ID。请求携带的 ID 仅用于发现旧标签页在账号切换后发错请求，发生不一致即返回 409。
- 原有家庭成员请求仍走 `profileId`，保持兼容。原生播放器会使用账号／成员身份隔离新产生的进度回调。
- 搜索历史、视频文件和下载任务不属于此次跨设备同步范围。

部署后，应在两台设备刷新页面。只验证一台设备显示「已同步」不能证明另一台尚未打开的设备已经完成补传。
