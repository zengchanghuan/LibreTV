# 点播来源优选

搜索结果展开后的来源列表与播放页“换源”列表共用检测和排序。检测仅在列表打开时执行；每组最多并发 3 条，关闭、换集或网络变化会取消旧请求。缓存按来源地址、详情地址、影片和集数区分，保留 5 分钟；网络变化会清空媒体抽样缓存；“重新检测”和定时刷新只使当前影片、集数的缓存失效。两者均保留本机实际播放记录，网络变化仅移除旧测速值。播放记录按原有 7 天有效期过期，反复测速不会延长其寿命。

## 检测进度与推荐

- 先检测本机播放记录中表现较好的候选，最多并发 3 条。
- 视频样本通过后立即参与排序、显示“当前推荐”并允许选择，字幕验证随后补充；无需等全部来源完成。
- 顶部推荐区显示来源名称、检测依据、操作按钮和“已检测 / 总数 · 通过数”。“已检测”包含视频已通过但仍在补充字幕的条目，字幕任务另行显示数量。
- 列表区分排队中、检测中、视频已通过／补充字幕中、检测完成、检测超时和检测未通过。全部失败时保留重测和手动选择入口。
- 搜索结果与换源面板使用相同推荐区；换源候选排除当前来源，保留当前集数和进度。关闭面板取消在途任务，旧结果不能回写。
- “检测说明”默认折叠，保留字幕未知与短时测速的解释。推荐是媒体抽样通过后的候选，不保证解码成功或整片流畅。

## 排序

1. 媒体测速通过且速度足够的来源优先；偏慢或近期实播明显卡顿的来源随后。未检测的来源再后，检测失败的排最后。
2. 同一速度档内，优先高清（至少 720p）且已验证字幕的来源；同条件优先中文字幕。
3. 同档再按本次响应耗时、抽样吞吐及本机实播记录比较。片源备注中的“1080p／中字”只作弱参考，不冒充检测结果。

速度通过最多读取约 128 KiB 媒体片段估算，界面显示 Mbps，禁止 HTTP 缓存命中冒充测速。低于 1.2 Mbps 或不足所选 HLS 流声明码率的 1.2 倍会标为偏慢。这是当前网络短时抽样，不保证持续速度、可解码性或播放流畅度。

## 清晰度与字幕边界

- HLS 主列表有多个分辨率时，检测分辨率最高的流，并读取对应流的片段；分辨率和码率来自该流的清单声明。
- 只检测所选流关联的字幕组，优先中文，最多尝试两条字幕轨，字幕检测总计最多 2.5 秒。
- 字幕需要取回包含实际时间轴及非空文本的 WebVTT 内容才标为“已检测字幕”。只有轨道声明、空字幕段、加密字幕、失败链接或不支持的字幕格式显示“字幕轨待验证”，不会导致本来可读取的视频变成失败。
- 没有轨道信息时显示“字幕未确认”，不表示没有字幕。画面烧录字幕、MP4 内封字幕和只有媒体分片的 HLS 暂不做解码识别。清晰度无法读取时也明确显示未确认。
- 代理同时重写 HLS 的字幕和音频轨 URI，保持重定向后的相对路径正确。

格式参考：[HLS RFC 8216](https://www.rfc-editor.org/rfc/rfc8216)。

## 验证

单元测试覆盖字幕组关联、中文字幕优先、真实 WebVTT 文本、代理 URI、字幕失败不影响视频探测、影片/集数缓存隔离、取消检测、慢速及失效资源降级。浏览器使用独立本地受控片源验证搜索来源与换源列表；该验证不代表外部片源的实际速度或字幕覆盖率。
