# 首页发现

精选首页展示当前成员续看、近期内容、本站热门和编辑精选。原豆瓣/百度等榜单保留在「更多参考榜单」，设置里的原榜单布局仍可回退。前台不出现模型品牌或生成方式文案；播放页的推荐辅助能力保留。

## 近期内容

`/api/home/discovery?sources=env_0,...` 只读取缓存。采集仅访问部署者 `DEFAULT_SOURCES` 中非成人 CMS 来源（最多 20 个），不扫描浏览器自定义地址。全局任务最多三个并发，每源两页，每请求八秒，30 分钟刷新一次。首次页面访问通过 `after()` 启动后台刷新；Node instrumentation 的同进程定时器每分钟检查一次到期任务。

新片必须有完整且有效的 `vod_pubdate`，至少两个选中来源日期一致，且没有冲突、在过去 90 天内、首映年份与标注日期年份差不超过一年；缺日期的作品只进最近收录，不能用 `vod_time` 或当前年份代替。片源之间可能共享上游资料，日期交叉核对不能替代独立发行证明，卡片保留来源依据而不宣称官方认证。

剧集首次采集只建立基线；之后同一片源条目的剧集数量增加才产生更新日期。更换 URL、海报或简介不算新增。影视、动漫、综艺沿用已有内容分类；预告、解说和成人条目不收录。

作品先匹配既有已核验目录，再按规范片名、年份、类型合并；剧名保留季数。资源按来源 URL 哈希及原站 ID 区分。最多保留 2,000 部作品，未观察到 30 天的来源清理；超过 24 小时未重新观察到的来源不进入首页有效计数。并非资源全部下架，只代表这次近期目录不再保证其新鲜度。卡片「已收录」不是可播放承诺，播放检查仍在用户选择片源时执行。

接口只返回当前选中来源的交集。未来年份的未核验片源条目不进入首页，旧缓存同样过滤，避免错误年份制造重复卡片。首个有内容的分类成为默认分类；新片日期不够时可先展示最近收录，不填充假新片。

## 赞、踩与个性化选片

新片上线、剧集更新、最近收录及猜你喜欢的赞/踩图标常驻海报右下角，采用独立浮层，不增加卡片高度，也不删减或缩写片名、年份、类型、日期、评分和片源等原有信息。图标与海报点击入口是同级元素，操作反馈不会打开详情；触屏保留 44×44 点击区域。选中后通过图标高亮表示状态，保存状态由读屏提示，不另占一行。同一影片在三个栏目共用状态；再次点击取消，点击另一项切换，保存中禁用重复操作。点踩立即从近期列表移除该片，并从已有后续内容补位，保留原日期排序；保存失败恢复原选择和列表，成功后可通过提示里的「撤销」恢复。

`/api/home/feedback` 沿用登录和同源校验，POST 最多 2 KiB，仅接受作品 ID 和 `like` / `dislike` / `null`。影片身份和导演、演员、题材取自服务端已核验目录或近期采集目录；不采信客户端提交的元数据或账号 ID。每个登录账号独立保存最近 1,000 部影片的当前选择、时间和精简资料，可跨设备读取；共享密码模式共用一份偏好，不按家庭合并。已离开近期目录的记录仍可切换或取消。

「为你精选」新增「猜你喜欢」，从完整精选目录按喜好生成三批不重复的影片。点赞提高相同导演、演员和具体题材的优先级；点踩排除该作品（兼容规范片名、别名和同年同类型作品），降低相近作品排序。保留原有成人过滤、导演/演员/系列重复限制和多样性规则。推荐卡片也能继续反馈：点踩立即移除，并从已加载的其他批次补位；同一次反馈保存响应返回重新排序的完整推荐，立即替换列表，不等下次轮询。保存失败恢复原列表；若只重排失败，保留已保存的反馈并立即重新请求推荐。没有反馈时沿用每日精选。

个性化排序只在服务端响应阶段执行，不写入公共每日推荐缓存，也不发送给外部推荐服务。读取反馈失败时展示重试提示，避免悄悄恢复包含点踩影片的通用推荐。热门榜与编辑片单仍保留各自的统计/编辑含义。

## 本站热门

新增 `/api/home/watch`，沿用登录及同源校验。客户端只发送已配置来源的 ID，服务端核验影片，客户端不能指定作品身份。网页播放器独立观察 video 的真实连续播放时间，暂停、缓冲、拖动、隐藏且非画中画的页面不累计。每 15 秒上报一次，后台最大按墙钟间隔计入，多标签共享账号时间预算；事件序号保证重试幂等。

正常影片累计观看五分钟合格；不足五分钟按 80% 时长、最低 30 秒合格。服务端仍依赖客户端播放信号，不能视为付费计费级反作弊。浏览器自定义片源、无法核验身份的作品，以及缺少可靠连续播放信号的原生播放器事件不纳入统计；不会从旧进度记录倒算观看量。

每部作品近七天同一账号只计一次，跨设备、家庭成员和片源去重。至少三个不同账号有效观看才展示。按独立账号数排序、最近有效观看时间打破并列；聚合结果按整点小时缓存，同一小时的排名保持稳定。共享密码模式算一个账号。初期真实样本不足，显示积累提示，禁止用外部热榜补足站内排名。

冷启动、无结果或接口失败时，使用随构建发布的九部目录影片和本地海报提供可点开的精选内容。近期区域先展示六部，热门区域改名「先看这些」展示另外三部；没有名次、观看量、新片日期或已验证片源数量，仍需点击查找片源。真实热门达到门槛后自动替换精选入口。编辑精选在首个响应前也有本地主题片单。所有影片卡面始终保留片名、年份和图形底图，封面加载中或全部失败都不会留下空白。

账号仅保存用途隔离的 HMAC，不保存姓名、IP、原始账号 ID。统计文件与会话均为服务端私有，接口只返回影片排序。观看贡献保留十四天；会话十分钟无心跳或六小时总长度过期；账号开始请求每小时最多六十次，心跳限流。后台定时清理。

## 编辑精选与审核

`src/lib/discovery-editorial.ts` 是版本化发布清单，预置三个经目录核验的专题，每个六部作品；北京时间每周一轮换主专题，其他专题可切换浏览。发布清单的片名、年份、封面和资料必须来自已核验目录。

复用已有服务端推荐客户端，每周从当前专题公开影片资料生成候选草稿，最多两次尝试。草稿位于 `discovery/editorial-draft.json`，不会被首页读取。维护者查看草稿、核对影片与理由后编辑发布清单，再通过代码审查、测试及部署发布。没有额外的公开管理 API；生成失败不会改变已发布内容。密钥保持服务端配置，不发送用户观看历史。

## 存储、开关与回退

所有运行数据在 `$LIBRETV_DATA_DIR/discovery/`：`catalog.json`、`watch.json`、`editorial-draft.json`、`feedback-<账号用途隔离 HMAC>.json`，未配置时优先使用 systemd 的 `STATE_DIRECTORY`，再回退已有 `.data` 根目录。反馈文件使用 `PROXY_SECRET`（未配置时使用 `PASSWORD`）派生账号标识，更换该密钥后旧记录不会自动迁移。生产环境应使用现有发布目录外的持久路径。单 Node 进程共享串行队列、唯一刷新任务和原子改名；不要从外部脚本同时写这些文件。多实例部署前必须改用共享数据库/锁。

- `HOME_DISCOVERY_RECENT=0` 隐藏近期模块。
- `HOME_DISCOVERY_POPULAR=0` 隐藏热门并停止接收观看事件。
- `HOME_DISCOVERY_EDITORIAL=0` 隐藏编辑精选并停用其草稿生成。
- `HOME_DISCOVERY_SCHEDULER=0` 停用定时刷新，仍允许页面触发到期刷新。

三个模块均禁用时停止后台任务。单个统计文件读取失败不阻断编辑精选。保留旧推荐 API 兼容；未修改家庭历史同步格式、播放器控制逻辑或既有记录。回滚构建只需原发布流程，新增文件可留在持久目录，不修改历史文件。

## 验证

回归覆盖日期合法性/冲突/选中来源隔离、旧片新入库、首次剧集基线、真正增集、同名重拍、过期来源、暂停与跳进度、服务器时间上限、多设备去重、账号隔离、短片阈值、七天排名和三账号门槛、十四天保留、原子文件并发、接口鉴权/同源/体积限制、编辑片单核验与周一边界。发布前运行 lint、typecheck、全量测试、生产构建，并验证桌面/手机 UI 和线上状态。
